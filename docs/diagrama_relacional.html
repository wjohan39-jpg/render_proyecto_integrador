Diagrama relacional

Proyecto Integrador · modelo de datos de los CSV en data/limpio/

Relaciones

  • empresa 1 — N reto: una empresa propone muchos retos (reto.id_empresa).
  • prioridad 1 — N reto: cada reto tiene un nivel de prioridad (reto.id_prioridad).
  • categoria 1 — N reto: cada reto pertenece a una categoría (reto.id_categoria).
  • reto 1 — N registro: un reto recibe muchas inscripciones (registro.id_reto).
  • usuario 1 — N registro: un usuario se inscribe en muchos retos (registro.id_usuario).
  • registro resuelve la relación N — M entre usuario y reto; la pareja (id_usuario, id_reto) es única, porque la limpieza elimina los duplicados.

Convenciones

PKclave primaria FKclave foránea Borde punteado: tabla que no existe en el proyecto ┼ un registro · ○< cero o muchos

Todas las claves son UUID. categoria y usuario solo aparecen como identificadores dentro de reto y registro: no tienen CSV propio (4 categorías y 150 usuarios distintos).

Ojo con los datos actuales

Las claves foráneas de los CSV no coinciden hoy con las tablas padre: 0 de 460 retos apuntan a una empresa o prioridad existente, y 0 de 720 registros apuntan a un reto existente. Cada tabla se simuló por separado, así que el diagrama muestra el modelo previsto, no uniones que funcionen con los datos tal como están. registros_limpio_adjunto.csv usa otro formato (R001, P01…) y queda fuera del modelo.
